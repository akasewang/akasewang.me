A table of contents needs one active entry, even when several headings are visible at once. That requirement is slightly different from asking which elements intersect the viewport.

`IntersectionObserver` is useful for visibility, but a scroll spy still needs policy on top of it: which intersecting heading wins, what happens during a fast jump and how the final short section becomes active when it can never reach the top threshold. Calculating the answer from the current geometry is often simpler than coordinating observer entry and exit events.

## Define a reading line

The active heading is the last heading that has crossed a fixed line 120 pixels below the viewport top. Walking the headings from bottom to top finds that heading directly.

```text
[ viewport top ] ---------------------------- 0 px

[ reading line ] ============================ 120 px

  Heading 1                                  already passed
  Heading 2                                  last heading above the line: active

  Heading 3                                  below the line
```

This rule remains deterministic when two short sections share the viewport. At the bottom of the document, the final heading is forced active because a short last section may never travel as far as the reading line.

## Measure at most once per frame

Scroll events can arrive more frequently than useful visual updates. The listener therefore schedules one `requestAnimationFrame` callback and ignores further scroll events until that callback runs.

```ts title="use-active-heading.ts"
import { useEffect, useState } from 'react'

export type TocItem = {
  id: string
  text: string
  level: number
}

export function useActiveHeading(items: TocItem[], offset = 120): string {
  const [activeId, setActiveId] = useState('')

  useEffect(() => {
    const headings = items.flatMap((item) => {
      const element = document.getElementById(item.id)
      return element ? [{ id: item.id, element }] : []
    })

    if (headings.length === 0) {
      setActiveId('')
      return
    }

    let frameId: number | null = null

    const measure = () => {
      const documentBottom = document.documentElement.scrollHeight - 1
      const viewportBottom = window.scrollY + window.innerHeight
      let nextId = headings[0].id

      if (viewportBottom >= documentBottom) {
        nextId = headings.at(-1)?.id ?? nextId
      } else {
        for (const heading of headings) {
          if (heading.element.getBoundingClientRect().top > offset) break
          nextId = heading.id
        }
      }

      setActiveId((currentId) => (currentId === nextId ? currentId : nextId))
      frameId = null
    }

    const scheduleMeasure = () => {
      if (frameId === null) frameId = window.requestAnimationFrame(measure)
    }

    window.addEventListener('scroll', scheduleMeasure, { passive: true })
    window.addEventListener('resize', scheduleMeasure)
    scheduleMeasure()

    return () => {
      window.removeEventListener('scroll', scheduleMeasure)
      window.removeEventListener('resize', scheduleMeasure)
      if (frameId !== null) window.cancelAnimationFrame(frameId)
    }
  }, [items, offset])

  return activeId
}
```

The scroll listener is passive because it never cancels scrolling. Heading elements are resolved once per effect rather than queried on every frame. Resize events use the same scheduler because a viewport change can alter which section crosses the reading line. Cleanup removes both listeners and cancels a frame that has not run yet.

This approach does call `getBoundingClientRect()` for headings during the scheduled frame. That is reasonable for a small article outline; a document with hundreds of headings might instead cache document offsets and refresh them after layout changes.

## Let anchors handle navigation

Use real fragment links for the table of contents. They preserve expected browser behavior such as copying a link, opening it in another tab and updating the URL hash. CSS `scroll-margin-top` supplies room for a fixed header without replacing native navigation with a click handler:

```css title="article.css"
.article :is(h2, h3, h4) {
  scroll-margin-top: 6rem;
}

@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}
```

The navigation margin and 120-pixel reading line are close but serve different purposes. One positions a selected heading comfortably; the other decides when normal scrolling advances the active state.

## Keep presentation independent

The component receives already parsed items. That keeps heading extraction separate from navigation and lets the same UI work with MDX, a CMS or headings supplied directly as data.

```tsx title="table-of-contents.tsx"
'use client'

import { type TocItem, useActiveHeading } from './use-active-heading'

// My implementation parses items from raw MDX and places this component in an
// article-width wrapper. The scroll-spy does not depend on either choice.
export function TableOfContents({ items }: { items: TocItem[] }) {
  const activeId = useActiveHeading(items)

  if (items.length === 0) return null

  return (
    <nav aria-label="On this page" className="sticky top-24">
      <p className="mb-4 text-sm font-medium">On this page</p>
      <ol className="space-y-2.5">
        {items.map(({ id, level, text }) => {
          const isActive = activeId === id

          return (
            <li key={id} className={level > 2 ? 'ml-5' : undefined}>
              <a
                href={`#${id}`}
                aria-current={isActive ? 'location' : undefined}
                className={`block truncate text-xs leading-tight ${
                  isActive ? 'font-medium text-slate-950' : 'text-slate-500 hover:text-slate-800'
                }`}
              >
                {text}
              </a>
            </li>
          )
        })}
      </ol>
    </nav>
  )
}
```

The wrapper around a sticky sidebar should provide the article's vertical boundary. That keeps the navigation visible while the article is on screen without making it permanently fixed to the viewport.

`IntersectionObserver` remains the right tool when visibility itself is the signal, such as lazy-loading media or recording impressions. For this TOC, a reading line expresses the desired behavior more directly and handles short final sections without observer bookkeeping.
