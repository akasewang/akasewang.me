A statically generated post can display a live view count without turning every card into a separate database request.

There are two distinct operations: listing cards read counts without changing them, while opening a post increments its count once per browser-tab session. A shared client provider batches the reads, and PostgreSQL handles concurrent writes.

```text
[ ViewCounter components ] → [ ViewsProvider ]
                                  ↓ one batched request
                          [ Route Handler ]
                                  ↓ one query
                            [ PostgreSQL ]
```

The standalone database examples use Drizzle with the `postgres` driver:

```bash
npm install drizzle-orm postgres server-only
```

## Define the database boundary

Keep the connection in a server-only module and fail clearly when its environment variable is absent:

```ts title="lib/db.ts"
import 'server-only'

import { drizzle } from 'drizzle-orm/postgres-js'
import postgres from 'postgres'

const connectionString = process.env.DATABASE_URL
if (!connectionString) throw new Error('DATABASE_URL is required')

const client = postgres(connectionString, { max: 10 })
export const db = drizzle(client)
```

The table has one row per routable slug:

```ts title="lib/schema.ts"
import { integer, pgTable, varchar } from 'drizzle-orm/pg-core'

export const pageViews = pgTable('page_views', {
  slug: varchar('slug', { length: 255 }).primaryKey(),
  count: integer('count').notNull().default(0),
})
```

Generate and apply a database migration for this schema before enabling either route. Declaring a Drizzle table in TypeScript does not create it in PostgreSQL.

The data functions validate their input, cap batch size and keep missing rows distinct from failed requests:

```ts title="lib/views.ts"
import 'server-only'

import { inArray, sql } from 'drizzle-orm'
import { db } from './db'
import { pageViews } from './schema'

const slugPattern = /^[a-z0-9]+(?:-[a-z0-9]+)*$/

export function normalizeSlug(value: string): string | null {
  const slug = value.trim().toLowerCase()
  return slug.length <= 255 && slugPattern.test(slug) ? slug : null
}

export async function readViewCounts(values: string[]): Promise<Record<string, number>> {
  const slugs = [...new Set(values.map(normalizeSlug).filter((slug): slug is string => !!slug))]
    .slice(0, 100)

  if (slugs.length === 0) return {}

  const rows = await db
    .select({ slug: pageViews.slug, count: pageViews.count })
    .from(pageViews)
    .where(inArray(pageViews.slug, slugs))

  const counts = Object.fromEntries(slugs.map((slug) => [slug, 0]))
  for (const row of rows) counts[row.slug] = row.count
  return counts
}

export async function incrementView(value: string): Promise<number> {
  const slug = normalizeSlug(value)
  if (!slug) throw new Error('Invalid slug')

  const [row] = await db
    .insert(pageViews)
    .values({ slug, count: 1 })
    .onConflictDoUpdate({
      target: pageViews.slug,
      set: { count: sql`${pageViews.count} + 1` },
    })
    .returning({ count: pageViews.count })

  if (!row) throw new Error('View increment returned no row')
  return row.count
}
```

The upsert is one database statement. Two visitors cannot both read the same count and overwrite one another with the same successor.

## Expose bounded Route Handlers

One endpoint can serve batched reads through `POST` and atomic writes through `PUT`. Sending the read batch as JSON avoids request-line limits when many cards mount together:

```ts title="app/api/views/route.ts"
import { incrementView, normalizeSlug, readViewCounts } from '../../../lib/views'

export async function POST(request: Request): Promise<Response> {
  const body: unknown = await request.json().catch(() => null)
  const slugs =
    body && typeof body === 'object' && 'slugs' in body && Array.isArray(body.slugs)
      ? body.slugs.filter((value): value is string => typeof value === 'string')
      : []

  try {
    return Response.json(
      { views: await readViewCounts(slugs) },
      { headers: { 'Cache-Control': 'no-store' } },
    )
  } catch (error) {
    console.error('Unable to read view counts', error)
    return Response.json({ views: null }, { status: 503 })
  }
}

export async function PUT(request: Request): Promise<Response> {
  const body: unknown = await request.json().catch(() => null)
  const rawSlug =
    body && typeof body === 'object' && 'slug' in body && typeof body.slug === 'string'
      ? body.slug
      : ''
  const slug = normalizeSlug(rawSlug)

  if (!slug) return Response.json({ error: 'Invalid slug' }, { status: 400 })

  try {
    return Response.json({ views: await incrementView(slug) })
  } catch (error) {
    console.error('Unable to increment view count', error)
    return Response.json({ views: null }, { status: 503 })
  }
}
```

Input validation is not abuse prevention. A public counter endpoint should also receive whatever rate limiting, bot filtering and observability match the value of the metric.

## Batch counters that mount together

The provider below is complete: it owns the queue, request lifecycle, result map and per-tab increment marker. Counters only register a slug and read its current state.

```tsx title="views-provider.tsx"
'use client'

import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useRef,
  useState,
  type ReactNode,
} from 'react'

type ViewValue = number | null
type ViewMap = Record<string, ViewValue>

type ViewsContextValue = {
  views: ViewMap
  requestViews: (slugs: string[]) => void
  incrementView: (slug: string) => Promise<void>
}

const ViewsContext = createContext<ViewsContextValue | null>(null)
const batchDelay = 50
const slugPattern = /^[a-z0-9]+(?:-[a-z0-9]+)*$/

function normalizeClientSlug(value: string): string | null {
  const slug = value.trim().toLowerCase()
  return slug.length <= 255 && slugPattern.test(slug) ? slug : null
}

function useViewsContext(): ViewsContextValue {
  const context = useContext(ViewsContext)
  if (!context) throw new Error('View counters must be rendered inside ViewsProvider')
  return context
}

export function ViewsProvider({ children }: { children: ReactNode }) {
  // My implementation also keeps a short-lived localStorage cache for successful
  // values. It is an optional paint optimization, so this example omits it.
  const [views, setViews] = useState<ViewMap>({})
  const viewsRef = useRef<ViewMap>({})
  const queued = useRef(new Set<string>())
  const loading = useRef(new Set<string>())
  const incrementing = useRef(new Set<string>())
  const countedThisSession = useRef(new Set<string>())
  const writeVersions = useRef<Record<string, number>>({})
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null)

  const commit = useCallback((updates: ViewMap) => {
    const next = { ...viewsRef.current, ...updates }
    viewsRef.current = next
    setViews(next)
  }, [])

  const fetchBatch = useCallback(
    async (requestedSlugs: string[]) => {
      const slugs = requestedSlugs.filter((slug) => !incrementing.current.has(slug))
      if (slugs.length === 0) return

      const versionsAtStart = Object.fromEntries(
        slugs.map((slug) => [slug, writeVersions.current[slug] ?? 0]),
      )
      slugs.forEach((slug) => loading.current.add(slug))

      try {
        const response = await fetch('/api/views', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ slugs }),
          cache: 'no-store',
        })
        if (!response.ok) throw new Error(`View request failed with ${response.status}`)

        const payload: unknown = await response.json()
        const rawViews =
          payload && typeof payload === 'object' && 'views' in payload ? payload.views : null
        if (!rawViews || typeof rawViews !== 'object') throw new Error('Invalid view response')

        const freshSlugs = slugs.filter(
          (slug) => (writeVersions.current[slug] ?? 0) === versionsAtStart[slug],
        )
        const next = Object.fromEntries(
          freshSlugs.map((slug) => {
            const value = (rawViews as Record<string, unknown>)[slug]
            const validCount =
              typeof value === 'number' && Number.isSafeInteger(value) && value >= 0
            return [slug, validCount ? value : null]
          }),
        )
        if (freshSlugs.length > 0) commit(next)
      } catch {
        const freshSlugs = slugs.filter(
          (slug) => (writeVersions.current[slug] ?? 0) === versionsAtStart[slug],
        )
        if (freshSlugs.length > 0) {
          commit(Object.fromEntries(freshSlugs.map((slug) => [slug, null])))
        }
      } finally {
        slugs.forEach((slug) => loading.current.delete(slug))
      }
    },
    [commit],
  )

  const requestViews = useCallback(
    (rawSlugs: string[]) => {
      let added = false

      for (const rawSlug of rawSlugs) {
        const slug = normalizeClientSlug(rawSlug)
        if (
          !slug ||
          typeof viewsRef.current[slug] === 'number' ||
          loading.current.has(slug) ||
          incrementing.current.has(slug) ||
          queued.current.has(slug)
        ) {
          continue
        }
        queued.current.add(slug)
        added = true
      }

      if (!added || timer.current !== null) return

      timer.current = setTimeout(() => {
        timer.current = null
        const slugs = [...queued.current]
        queued.current.clear()
        if (slugs.length > 0) void fetchBatch(slugs)
      }, batchDelay)
    },
    [fetchBatch],
  )

  const incrementViewForSession = useCallback(
    async (rawSlug: string) => {
      const slug = normalizeClientSlug(rawSlug)
      if (!slug) return

      const sessionKey = `viewed:${slug}`
      let alreadyCounted = countedThisSession.current.has(slug)

      try {
        alreadyCounted ||= sessionStorage.getItem(sessionKey) === 'true'
      } catch {
        // Storage can be unavailable in restricted browser contexts.
      }

      if (alreadyCounted) {
        requestViews([slug])
        return
      }
      if (incrementing.current.has(slug)) return
      incrementing.current.add(slug)
      queued.current.delete(slug)
      writeVersions.current[slug] = (writeVersions.current[slug] ?? 0) + 1

      try {
        const response = await fetch('/api/views', {
          method: 'PUT',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ slug }),
        })
        if (!response.ok) throw new Error(`View increment failed with ${response.status}`)

        const payload = (await response.json()) as { views?: unknown }
        if (
          typeof payload.views !== 'number' ||
          !Number.isSafeInteger(payload.views) ||
          payload.views < 0
        ) {
          throw new Error('Invalid increment response')
        }

        commit({ [slug]: payload.views })
        countedThisSession.current.add(slug)
        try {
          sessionStorage.setItem(sessionKey, 'true')
        } catch {
          // The in-memory marker still prevents duplicates for this provider lifetime.
        }
      } catch {
        commit({ [slug]: null })
      } finally {
        incrementing.current.delete(slug)
      }
    },
    [commit, requestViews],
  )

  useEffect(() => {
    return () => {
      if (timer.current !== null) clearTimeout(timer.current)
    }
  }, [])

  const value = useMemo(
    () => ({ views, requestViews, incrementView: incrementViewForSession }),
    [incrementViewForSession, requestViews, views],
  )

  return <ViewsContext.Provider value={value}>{children}</ViewsContext.Provider>
}

export function useViewCount(slug: string, shouldIncrement = false): ViewValue | undefined {
  const { incrementView, requestViews, views } = useViewsContext()
  const normalizedSlug = normalizeClientSlug(slug) ?? ''

  useEffect(() => {
    if (!normalizedSlug) return
    if (shouldIncrement) void incrementView(normalizedSlug)
    else requestViews([normalizedSlug])
  }, [incrementView, normalizedSlug, requestViews, shouldIncrement])

  return normalizedSlug ? views[normalizedSlug] : null
}
```

```tsx title="view-counter.tsx"
'use client'

import { useViewCount } from './views-provider'

export function ViewCounter({ slug, increment = false }: { slug: string; increment?: boolean }) {
  const views = useViewCount(slug, increment)

  if (views === undefined) return <span aria-label="Loading views">—</span>
  if (views === null) return <span>Views unavailable</span>
  return <span>{views.toLocaleString()} views</span>
}
```

The map intentionally has three states: `undefined` means no response yet, a number includes a valid zero, and `null` means the request failed. Failures are not mistaken for new posts with no views.

`writeVersions` prevents an older batch read from overwriting a newer increment response. Starting an increment advances that slug's version; a read only commits if the version it captured is still current.

The session marker is written only after a successful increment. This is deliberate deduplication, not unique-visitor analytics: a new tab, browser or cleared session can count again.

Static delivery and live counts do not have to compete. The page remains cacheable because the small changing value arrives through a shared client store, while the server receives one bounded batch read or one atomic write for the work actually requested.
