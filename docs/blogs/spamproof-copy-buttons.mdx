A copy button has one job, but several details can make it feel unreliable. Rapid presses can leave competing reset timers. Swapping icons can move nearby content. A successful clipboard write may not produce enough feedback to distinguish it from a missed click.

The implementation below handles those cases without depending on an application-specific component library. It uses [`framer-motion`](https://www.npmjs.com/package/framer-motion) for animation and [`lucide-react`](https://www.npmjs.com/package/lucide-react) for the two icons.

```bash
npm install framer-motion lucide-react
```

## Load motion once

The component uses Framer Motion's `m` elements, whose features are supplied by `LazyMotion` higher in the tree. `MotionConfig` also applies the reader's reduced-motion preference to every descendant animation.

```tsx title="motion-provider.tsx"
'use client'

import { domAnimation, LazyMotion, MotionConfig } from 'framer-motion'
import type { ReactNode } from 'react'

export function MotionProvider({ children }: { children: ReactNode }) {
  return (
    <LazyMotion features={domAnimation} strict>
      <MotionConfig reducedMotion="user">{children}</MotionConfig>
    </LazyMotion>
  )
}
```

Place the provider once near the root of the client-side interface. Individual animated controls can then use `m` without each configuring the feature bundle.

## Keep the icon slot stable

The copy and check icons do not have identical SVG bounds. Both render inside a wrapper with an explicit width and height, and each animated icon is positioned absolutely within it.

    ```tsx title="animated-copy-icon.tsx"
      return (
        <span className="relative size-4">
          <AnimatePresence initial={false} mode="popLayout">
            <m.span key={copied ? 'check' : 'copy'} className="absolute inset-0">

            </m.span>

    }
    ```
  </Tab>

The fixed wrapper protects the surrounding layout. `AnimatePresence` keeps the outgoing icon mounted long enough to finish its exit animation, while `popLayout` prevents it from claiming extra layout space during the swap.

## Use one owner for each async concern

This complete button prevents concurrent clipboard writes, keeps exactly one reset timer and only displays success after the browser confirms the write:

```tsx title="copy-button.tsx"
'use client'

import { AnimatePresence, m } from 'framer-motion'
import { Check, Copy } from 'lucide-react'
import { useEffect, useRef, useState } from 'react'

type CopyButtonProps = {
  value: string
  label?: string
  resetAfter?: number
  className?: string
  onCopySuccess?: () => void
  onCopyError?: (error: unknown) => void
}

export function CopyButton({
  value,
  label = 'Copy to clipboard',
  resetAfter = 1500,
  className = '',
  onCopySuccess,
  onCopyError,
}: CopyButtonProps) {
  // My implementation can also accept parent-controlled copy state. This
  // standalone version keeps one clear state owner.
  const [copied, setCopied] = useState(false)
  const [isWriting, setIsWriting] = useState(false)
  const writeInFlight = useRef(false)
  const resetTimer = useRef<ReturnType<typeof setTimeout> | null>(null)

  useEffect(() => {
    return () => {
      if (resetTimer.current !== null) clearTimeout(resetTimer.current)
    }
  }, [])

  async function handleCopy() {
    if (writeInFlight.current) return

    writeInFlight.current = true
    setIsWriting(true)

    try {
      await navigator.clipboard.writeText(value)
      setCopied(true)
      onCopySuccess?.()

      if (resetTimer.current !== null) clearTimeout(resetTimer.current)
      resetTimer.current = setTimeout(() => {
        setCopied(false)
        resetTimer.current = null
      }, resetAfter)
    } catch (error) {
      onCopyError?.(error)
    } finally {
      writeInFlight.current = false
      setIsWriting(false)
    }
  }

  const Icon = copied ? Check : Copy

  return (
    <m.button
      type="button"
      aria-label={copied ? 'Copied' : label}
      disabled={isWriting}
      onClick={handleCopy}
      whileTap={{ scale: 0.94 }}
      transition={{ type: 'spring', stiffness: 500, damping: 30 }}
      className={`inline-flex items-center justify-center disabled:cursor-wait ${className}`}
    >
      <span className="relative size-4" aria-hidden="true">
        <AnimatePresence initial={false} mode="popLayout">
          <m.span
            key={copied ? 'check' : 'copy'}
            initial={{ scale: 0.5, opacity: 0, rotate: -45 }}
            animate={{ scale: 1, opacity: 1, rotate: 0 }}
            exit={{ scale: 0.5, opacity: 0, rotate: 45 }}
            transition={{ duration: 0.2, ease: [0.23, 1, 0.32, 1] }}
            className="absolute inset-0 flex items-center justify-center"
          >
            <Icon size={16} strokeWidth={2} />
          </m.span>
        </AnimatePresence>
      </span>
      <span className="sr-only" aria-live="polite">
        {copied ? 'Copied to clipboard' : ''}
      </span>
    </m.button>
  )
}
```

The ref closes the tiny interval before React commits the disabled state, so repeated presses cannot start overlapping clipboard operations. Later successful presses replace the existing timeout rather than leaving stale callbacks racing to hide the checkmark. Cleanup also cancels the pending callback if the button unmounts.

The clipboard operation is awaited before success state appears. That matters because permissions, an insecure context or browser policy can reject `navigator.clipboard.writeText()`. A failed write should not show a successful checkmark; the optional error callback lets the surrounding interface display a toast or fallback message.

The motion is intentionally brief. Its purpose is to acknowledge the press and make the state change legible, not to turn copying into a spectacle. Stable geometry, one reset timer and honest success handling do most of the work.
