Tailwind classes work best when the compiler can see complete class names. Runtime values are different. A callout with several variants may need related colors for its background, border, label, links and inline code.

Interpolating `bg-${color}-500/20` is unreliable because the generated class name does not exist as a static string for Tailwind to detect. A mapping object works, but repeating every utility for every variant quickly becomes hard to maintain:

```tsx title="variant-classes.ts"
const CLASSES = {
  info: 'bg-blue-600/10 border-blue-500/30 text-blue-300',
  success: 'bg-emerald-600/10 border-emerald-500/30 text-emerald-300',
}
```

The component only needs one runtime input: its accent color. A CSS custom property can carry that value through a fixed set of Tailwind utilities.

## Pass data through a custom property

Each variant defines an OKLCH color. The component assigns it to `--callout-hue` on the wrapper, and descendant styles derive their colors from that property.

```text
[ React component ] → style={{ '--callout-hue': 'oklch(0.7 0.15 60)' }}
                              ↓
[ Static utility ]   ← bg-[color-mix(in_oklab,var(--callout-hue)_6%,transparent)]
```

Tailwind still sees a complete class name at build time. The browser supplies the changing value at runtime, so there is no safelist and no class-name generation in JavaScript.

## Why OKLCH and `color-mix()` work well here

OKLCH represents a color with lightness, chroma and hue. Holding lightness and chroma near the same values while changing hue usually produces accents with more consistent perceived brightness than equivalent HSL colors. It does not guarantee equal contrast, so each final foreground and background combination still needs to be checked.

The browser's `color-mix()` function derives surfaces from the accent. This example mixes a small amount of the active hue into a dark base:

```css
background-color: color-mix(in oklab, var(--callout-hue) 6%, oklch(0.23 0 0 / 30%));
```

The complete component below depends only on React and Tailwind. It keeps labels and hues in a small variant map while leaving the related surface colors to CSS:

```tsx title="callout.tsx"
import { useId, type CSSProperties, type ReactNode } from 'react'

type CalloutType = 'info' | 'tip' | 'warning' | 'error' | 'success'

type CalloutProps = {
  type?: CalloutType
  title?: ReactNode
  children: ReactNode
  className?: string
}

type CalloutStyle = CSSProperties & { '--callout-hue': string }

const VARIANTS: Record<CalloutType, { label: string; hue: string }> = {
  info: { label: 'Note', hue: 'oklch(0.68 0.16 250)' },
  tip: { label: 'Tip', hue: 'oklch(0.68 0.16 300)' },
  warning: { label: 'Warning', hue: 'oklch(0.76 0.15 70)' },
  error: { label: 'Error', hue: 'oklch(0.68 0.18 20)' },
  success: { label: 'Success', hue: 'oklch(0.7 0.16 155)' },
}

export function Callout({ type = 'info', title, children, className = '' }: CalloutProps) {
  const { label, hue } = VARIANTS[type]
  const labelId = useId()

  return (
    <aside
      aria-labelledby={labelId}
      style={{ '--callout-hue': hue } as CalloutStyle}
      className={`my-6 overflow-hidden rounded-xl border border-[color-mix(in_oklab,var(--callout-hue)_28%,transparent)] bg-[color-mix(in_oklab,var(--callout-hue)_6%,transparent)] ${className}`}
    >
      <div className="flex items-center gap-2 px-4 pb-0 pt-3">
        {/* My implementation uses an icon map; this marker avoids that dependency. */}
        <span
          aria-hidden="true"
          className="size-2 rounded-full bg-[var(--callout-hue)] shadow-[0_0_0_3px_color-mix(in_oklab,var(--callout-hue)_16%,transparent)]"
        />
        <span id={labelId} className="text-xs font-medium text-[var(--callout-hue)]">
          {title ?? label}
        </span>
      </div>

      <div className="px-4 pb-3 pt-2 text-sm leading-relaxed text-slate-200 [&_a]:font-medium [&_a]:underline [&_a]:decoration-[color-mix(in_oklab,var(--callout-hue)_45%,transparent)] [&_a]:underline-offset-[3px] [&_a:hover]:decoration-[var(--callout-hue)] [&_code]:rounded [&_code]:bg-[color-mix(in_oklab,var(--callout-hue)_12%,transparent)] [&_code]:px-[0.35em] [&_code]:py-[0.1em]">
        {children}
      </div>
    </aside>
  )
}
```

## One inherited value, several treatments

Custom properties inherit, so nested elements can use the same accent without receiving additional React props.

The inline-code rule mixes 12% of `--callout-hue` into transparency:

```text
[&_code]:bg-[color-mix(in_oklab,var(--callout-hue)_12%,transparent)]
```

The link rule uses 45% of the accent for its underline and the full accent on hover:

```text
[&_a]:decoration-[color-mix(in_oklab,var(--callout-hue)_45%,transparent)]
[&_a:hover]:decoration-[var(--callout-hue)]
```

Those utilities are static; only the inherited color changes. Adding a variant requires one new entry in `VARIANTS`, not another copy of every background and descendant rule.

This pattern is useful whenever a finite component structure depends on runtime design data. Tailwind handles layout and selectors, React supplies the value, and CSS performs the color derivation where it naturally belongs.
